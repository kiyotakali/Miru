Miru 记忆系统 v3 — 输入到输出全链路

保留 4-pass router 作为质量内核 · 砍掉真冗余（双队列、translate 层、双视图）
数据真理统一到 facts.json · 用户视角 ≡ Miru 视角 (renderer)

1. 整体架构（基于实际代码）

用户输入 VLM 主对话 LLM 4-pass router LLM 存储 渲染 输出 不进 memory
INPUT-A 用户聊天文字 POST /api/chat
用户在前端发消息 → core.handle_user_message(text)
↓
SYNC-1 Chat Agent 主对话 1 LLM (chat tier)
prompt._build_agent_system_prompt 注入 identity ground truth + active slot overview（来自 renderer） → 主对话 LLM 生成 reply → 立刻 return 给前端，不等记忆写完。
↓ (reply 已 return) ⇣ 异步触发
ASYNC 4-Pass Router (后台线程) 3-4 LLM (memory tier) fire-and-forget
memory_router.trigger_route_async(content, source_type="chat")

Pass 1 — Domain 分类：person / project / topic / self / none
Pass 2 — Slot 路由：看全部现有 slots + aliases，决定 match 还是 new
Pass 3 — Metadata（仅 new slot）：稳定 kebab-case id + 标题 + icon
Pass 4 — Fact 抽取：从内容抽原子事实，比对现有 facts

⚠️ 每个 Pass 的 system prompt 都注入了 identity ground truth。
↓
MERGE fact_resolver.reconsider (纯 Python) 无 LLM · ~5 ms
新事实 vs 现有事实，确定性仲裁：reinforce (+0.15) / supersede (高置信吃低置信) / reject_pinned / reject_lowconf。
30 天没加固自动 ×0.9 衰减。
↓
STORE facts.json 单一真理 原子写
slots/<domain>/<slot_id>/facts.json 原子替换。
同时更新 _slots/<domain>.json 的 slot 元数据 (last_active, status)，重建 memory/index.md。
↓
SSE memory_changed 推前端 广播
sse.broadcast("memory_changed", {domain, slot_id, action})
前端记忆栏目立刻拉新 slot 卡，用户看到事实更新（典型 7 秒）。

截屏链路（结构对称）

INPUT-B 桌面 / 手机截屏 POST /api/device/screenshot
sensor 拍图 → 上传 → screen_analyzer.analyze(jpeg_bytes)
先写 screenshot_log.json（活动痕迹，sleep_inference 用）。
↓
VLM VLM 一句话观测 1 LLM (vision tier)
call_screen_observation(image) → "显著性数字 | 一句话描述"。
prompt 注入 identity 用户名 hint 防 OCR 误读 (李垦↔李昱)。
同时 push care_engine.notify_signal("screenshot")。
↓ 同上 4-pass router (异步) → facts.json

onboarding / 设置页（直写，无 LLM）

INPUT-C 权威身份直写 无 LLM
identity.update({name, role, occupation, ...})
→ 写 identity.json 镜像备份
→ curator.cascade_identity → slots/self/identity/facts.json
所有 fact 标记 pinned · confidence 1.0 · source=identity。

Miru 主动消息（不进记忆）

PROACTIVE CareEngine + 早安消息 无记忆写入
Miru 主动说话 = CareEngine v3 自己 LLM 决策 + _deliver()， 或定时早安走 _send_via_agent。
都不进 router — Miru 自言自语不变事实，避免反馈环。

2. 置信度仲裁规则（fact_resolver）

来源 (source_type)初始置信度一句话理解
identity 1.00 (pinned) onboarding/设置页直接写，永不被推翻
user_chat 0.70 用户在对话里直说
user_implicit 0.50 从用户行为/语气推断
screenshot_text 0.30 截屏 OCR / 场景描述
screenshot_inf 0.20 VLM 看图猜（最不可信）
  • 加固：再次看见同一事实 → confidence + 0.15（封顶 1.0）
  • 取代：高置信吃低置信，旧的标 superseded（保留历史）
  • 钉子：identity 派生的 pinned facts 永远不被推翻
  • 衰减：30 天没被加固一次 → ×0.9（pinned 不衰减）
  • 渲染门槛：confidence < 0.30 不渲染到 main.md（仍在 facts 里）

5. 为什么坚持 4 次 LLM 调用而不是合并成 1 次？

Pass它真正做的事为什么必须独立
Pass 1
Domain		 把"项目协作群"放到 project 而不是 person 边角分类需要专门的 prompt 工程，混在大 prompt 里会被稀释
Pass 2
Slot Route		 "晨阳..." → 已有 person/si-chenyang 而不是新建 必须看全部现有 slots + aliases。这是 retrieval 问题，看不到全景必出错
Pass 3
Metadata		 给新 slot 稳定 kebab-case id + collision check id 漂移会导致同一项目出现 contextlife / context-life / miru-project 多张卡
Pass 4
Fact 抽取		 从内容抽原子事实，比对 slot 现有 facts 看 facts 列表才能判断"是新事实还是加固已有事实"
每个 Pass 看不同的上下文：Pass 2 看 slot inventory，Pass 3 看 used ids， Pass 4 看 slot facts。压到一个 prompt 等于让 LLM 同时做 4 件需要不同输入的事——做不好。

6. 这次重构砍掉的冗余

砍掉的东西为什么是冗余
sleep_agent + summarizer 双队列 它们的 cheap LLM 总结又被 router 重新分类，等于做了一次没人用的中间总结
3 分钟 debounce 记忆延迟 3 分钟无意义。改成异步 fire-and-forget，立刻触发，不卡 chat reply
try_route_legacy_op 翻译层 把旧 LLM 输出的 path 翻译成 domain hint —— 既然 chat / screenshot 直接调 router 就不需要
Miru 主动消息进 sleep_agent Miru 自言自语反馈环：让自己的话变成"事实"。已删 (Phase A)
用户名同时存 4 处 identity.json + self_profile.json + core_memory.human + slot facts → 现统一到 slots/self/identity/facts
UI 卡片 vs archival_search 各自渲染 同一份 facts.json 出两套样式 → 数据真理可能漂移。已统一到 renderer.render_slot

7. LLM 数对比

动作旧最坏情况简化后
用户一条聊天消息 chat 1 + sleep_agent 1 + router 4 = 6 chat 1（同步）+ router 4（异步）= 5
一次截屏 VLM 1 + summarizer 1 + router 4 = 6 VLM 1（同步）+ router 4（异步）= 5
Miru 主动消息 CareEngine 1 + sleep_agent 1（错误）= 2+ CareEngine 1（不进 memory）= 1
onboarding 5 字段填写 0（直写）+ cascade 4 文件 0（直写到 slot facts，单文件）
LLM 数没大幅减少 —— 简化的目标不是省成本，是把数据真理统一、删掉模糊路径、让用户看到的和 AI 用的一致。

9. 一句话总结

4-pass router 是质量内核（保留）：每个 Pass 看不同上下文做专业决策，不能合并。
真冗余被砍光（双队列、translate 层、双视图、自言自语反馈环）：异步触发 + 单一渲染 + Miru 主动消息隔离。
数据真理只在 facts.json：UI 卡片和 Miru prompt 走同一个 renderer.render_slot，绝不漂移。
